# Coursework submission checklist

- [ ] Project opens on university-compatible Windows Android Studio and runs on its emulator.
- [ ] `gradlew.bat testDebugUnitTest lintDebug assembleDebug` succeeds; attach results.
- [ ] Demonstrate Must: UI, interactivity, configuration state.
- [ ] Demonstrate Should: list, ViewModel/StateFlow, navigation, internet, graceful errors.
- [ ] Demonstrate Could: Room offline cache, WorkManager sync, and additional chart/adaptive UI.
- [ ] `design.md` contains developer name/ID, features mapped to rubric, wireframes, state hoisting, MVVM/UDF, Room schema, API JSON, navigation and resilience.
- [ ] `security-review.md` audits permissions, local storage, HTTPS and remaining risks.
- [ ] `tool-review.md` reflects on actual tools and decisions.
- [ ] README includes name/ID and honest AI disclosure.
- [ ] `ai-log.md` includes genuine logs or links; reflection covers at least two actual AI errors and their diagnosis/correction.
- [ ] Code and reused material attributed where needed.
- [ ] Authentic GitHub commit history, module coordinator invited, final branch identified.
- [ ] Download ZIP **from GitHub**, submit ZIP and repository URL to Moodle.
- [ ] If aiming for Play Store: replace sample application ID, review target API policy, public privacy policy and current Play requirements.
